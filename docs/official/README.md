## 一、它是什么

一台 **25 cm、800 g 的双足机器鸭**，用强化学习训出来的神经网络策略走路。官方售价 $399。

官方 README 的原话：**"This repo is the duck's brain."** —— 一块 Rockchip RK3566 板上跑着一组 daemon，一个 50 Hz 控制环用神经策略驱动十五个舵机，外加无线电、摄像头，以及"能给机器人换软件而不变砖"的更新机制。

## 二、拆成三句话

**第一句：所有智能都在一个 50 Hz 的循环里。**

每秒 50 次，每次做三件事 —— 读全部 16 个设备（15 个舵机 + 1 个 IMU，**一次**总线事务）、把读数拼成一个 61 个数的向量喂给神经网络、把网络吐出的 14 个数写回舵机。就这样。

≈ 一个固定频率的事件循环，只是**迟到就是故障**。

**第二句：七个进程，只有一个能碰电机。**

`robotd` 独占串口总线和 50 Hz 环。其余六个是传输层和传感器 —— 手柄、蓝牙、摄像头、深度、配置、更新 —— 它们发**意图**（"这么快走"、"看那边"），由 `robotd` 的安全层决定什么真正可执行。

≈ 一个单写者架构。所有写操作串行经过一个进程。

**第三句：软件整体替换，而且会自己回滚。**

一个版本落成一整个目录，切符号链接，重启，然后问"你还健康吗"。不健康就自己换回去。

≈ 蓝绿部署 + 健康检查 + 自动回滚，只是跑在一块巴掌大的板子上。

## 三、身上有什么

### 15 个舵机 —— 关节全在这里

✅ 读自源码 `duck-ipc-proto` 的 `JOINT_NAMES`（顺序即协议）：

| 部位 | 数量 | 关节 |
|---|---|---|
| **左腿** | 5 | `hip_yaw` `hip_roll` `hip_pitch` `knee` `ankle` |
| **右腿** | 5 | 同上 |
| **颈 / 头 / 嘴** | 5 | `neck_pitch` `head_pitch` `head_yaw` `head_roll` `mouth` |

**腿 10 + 颈头嘴 5 = 15。** 髋关节有三个自由度（偏航/横滚/俯仰），所以单腿就 5 个。

⚠️ **策略只控制 14 个** —— `mouth`（索引 9）不进动作空间，由独立逻辑驱动。

### 电子件装在哪

```
头（MJCF 里叫 jaw_soft 刚体，中间没有关节）
 ├── Radxa Zero 3W        主控 —— 跑 Linux、神经网络、视觉
 ├── RPI Robot HAT        叠在主控上方 7.3mm —— 配电 + 音频 + 舵机总线收发
 ├── IMX219 摄像头        眼睛（⚠️ 转 90° 安装）
 ├── ToF 模组             8×8 区测距（⚠️ 不是激光雷达）
 └── 喇叭

躯干（trunk_base）
 ├── 两颗 hip_yaw 舵机     内腔基本被这两颗占满
 └── imu_to_dxl 板        把 IMU 伪装成第 16 个总线设备

外挂：NP-F550 电池，在机身后下方，71mm 长有约 40mm 悬在壳体外
```

⚠️ **最反直觉的一条：主控在头里，不在躯干。** 这直接决定你买多长的排线。

⚠️ **穿过脖子的只有两样**：舵机总线（1 对线）和电池供电线。摄像头排线**不过脖子** —— 摄像头和主控在同一刚体里。

完整清单与架构图见 [hardware.md](hardware.md)。

## 四、一秒钟里发生什么

```
每 20 ms：
  ① 一次 sync_read   ← 16 个设备（IMU 排第一）一次问完
  ② 拼观测 61 维     ← 角速度3 + 重力投影3 + 关节位置15 + 速度15 + 上次动作15 ...
  ③ 神经网络推理     ← 61 进 14 出
  ④ 一次 sync_write  → 15 个关节目标位置

每 1 s：额外读一次电压与温度
```

两次总线事务，一次推理。**没有第三次。**

## 五、四条最该记住的设计决策

**只有 `robotd` 能碰电机。** 客户端发意图不发指令，安全层做最终裁决。

**三个 daemon 能在 `robotd` 死后存活。** `configd` / `updaterd` / `btd` 对它无 systemd 依赖 —— 原话是：控制环起不来的机器人，正是最需要被重配、更新、回滚的那台。

**跌倒判定只上报，不拦截。** 没有"摔了就锁死"这回事。躺在地上按 Start 就是让它站起来的正常方式。

**`robotd` 从不自己让机器人动。** 启动时读当前位置当作目标、不碰扭矩。所以更新重启时，站着的机器人会继续站着。

## 六、常见误解三连

1. **没有激光雷达。** ToF 是 8×8 区的测距模组。
2. **音频不是独立模块。** codec、功放、麦克风全在 HAT 上。
3. **主控不在躯干，在头里。**

## 七、它和"复刻"的关系

官方**软件全部开源**（Apache-2.0），**硬件设计文件没有**：

| 部分 | 开源？ |
|---|---|
| Rust 控制栈、RL 训练环境、9 个出厂策略 | ✅ Apache-2.0 |
| MJCF 仿真模型 + STL | 公开，但 **CC BY-NC-SA 4.0** |
| RPI Robot HAT | ✅ 完整 KiCad + gerber + BOM |
| 机械设计文件、`imu_to_dxl` 板 | ❌ **从未发布** |

所以"复刻"的真实含义是：**软件是改造，硬件才是逆向。** 详见 [../rebuild/](../rebuild/)。
