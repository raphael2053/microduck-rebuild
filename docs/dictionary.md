# 术语表

给软件工程师看的机器人硬件词典。

词条全部来自 `fanhao375/microduck-replica` 与 `AI-FanGe/Microduck-build-tutorial` 两个仓库的文档、BOM 与提交历史（扫描日期 2026-09-15），不是通用词表 —— 收的是**这个项目真会遇到的词**。

读法：每条一句话说清「它是什么」。带 `≈` 的是后端类比，只求直觉对，不求严格等价。带 ⚠️ 的是容易踩的坑。

## 一、先破除三个误解

这三条在 `fanhao375` 的硬件入门文档里被专门拎出来，因为几乎人人都搞错：

- **Microduck 没有激光雷达。** 它装的是 ToF 测距模组（8×8 个测距点），不是会转的雷达。
- **主控不在肚子里，在头里。** 这直接决定你买多长的排线。
- **音频不是独立模块。** 声卡、功放、麦克风全集成在 HAT 那块板上。

## 二、最基础的十个词

先记住这十个，剩下的都好办。

| 术语 | 简称 | 一句话 |
|---|---|---|
| **BOM**（Bill of Materials，物料清单） |  | 造一台机器需要买的所有东西的清单，含型号、数量、单价。≈ `package.json` 的依赖表，但每一项都要花钱、有交期 |
| **舵机**（servo） |  | 能被命令"转到 30 度"并自己保持住的电机，机器人的关节肌肉。≈ 一个幂等的 `setPosition()` 接口，内部自带闭环 |
| **执行器**（actuator） |  | 舵机的学名，泛指"把电变成动作"的部件。与传感器（把物理量变成电）相对 |
| **PCB**（Printed Circuit Board，印制电路板） |  | 那块绿色的板子，元件焊在上面，铜走线代替电线。≈ 编译产物，设计文件才是源码 |
| **原理图**（schematic） |  | 电路的逻辑连接图，只说"谁连谁"，不管物理位置。≈ 架构图 |
| **公差**（tolerance） |  | 允许的尺寸误差范围，例如孔标称 Ø2.2 但实际 2.15–2.25 都算合格。≈ 浮点比较里的 epsilon。⚠️ 3D 打印件装不上，九成是公差没留够 |
| **紧固件**（fastener） |  | 螺丝、螺母、垫片这类把零件固定在一起的标准件的统称。这台机器约 325 个 |
| **总线**（bus） |  | 一根线上挂多个设备、靠地址区分的通信方式。≈ 共享消息总线，只是物理上真的是一根线 |
| **IMU**（Inertial Measurement Unit，惯性测量单元） |  | 测量自身姿态和加速度的芯片，机器人的内耳。没有它双足机器人站都站不住 |
| **MJCF** |  | MuJoCo 仿真器的模型格式（XML），描述机器人有哪些刚体、关节、质量。≈ 仿真世界的 schema 定义 |

## 三、本项目的专有名词

前两节是通用概念。这一节是**只在 Microduck 里出现的名字** —— 两块自制板、器件型号、上游的进程名。读文档卡住，多半卡在这里。

### 两块自制板

#### `imu_to_dxl` —— 名字就是功能说明书

拆开念：`imu` = 惯性测量单元，`dxl` = **D**yna**m**i**x**e**l** 的通用缩写（舵机总线）。连起来就是 **"把 IMU 接到 Dynamixel 总线上"** 的那块板。

**为什么需要它**：主控和 15 个舵机之间只有一条半双工总线。IMU 本身是 SPI/I²C 器件，协议对不上，挂不上去。这块板上放一颗小 MCU（STM32G031），对内用 SPI 读 IMU，对外**假装自己是第 16 个舵机**（ID 200）—— 主控用"读舵机寄存器"的方式就能拿到姿态数据。

**好处**：姿态和 15 个舵机的状态在**同一次 `sync_read`** 里一起读回，不额外占总线、不占主控算力（IMU 芯片内置 SFLP，直接吐四元数）。

≈ 给一个协议不兼容的数据源套一层 adapter，让它符合既有接口，调用方一行都不用改。

⚠️ 官方从未公开这块板的任何设计文件。目前有两份独立的社区重建，**都没有流片验证过** —— 这是整个硬件线风险最高的单点。

#### `RPI Robot HAT` —— 常简称 HAT

**HAT** 是树莓派生态对"叠在主板上方的扩展板"的叫法（Hardware Attached on Top）。一块板干四件事：配电、音频（codec + 功放 + 麦克风）、舵机总线接口、关机检测。

⚠️ 名字里的 "RPI" 是历史遗留 —— 实际主控是 Radxa 不是树莓派，只是沿用了树莓派的 40 针形态。这是**唯一一块官方完整开源**的板（KiCad + Gerber + BOM + 贴片坐标齐全）。

### 模型文件里的名字

MJCF 是 XML，下面这些是里面的标签和刚体名 —— 社区的零件数量统计全靠数它们。

| 名字 | 简称 | 是什么 |
|---|---|---|
| **`geom`** |  | MJCF 里的几何体元素，负责碰撞与显示。**数某个网格被 `geom` 引用几次 = 整机用了几个** |
| **`body`** |  | MJCF 里的刚体标签，`geom` 和关节都挂在它下面 |
| **`robot_walk.xml`** | walk.xml | 行走任务的 MJCF 模型。社区的数量统计大多以它为基准 |
| **`jaw_soft`** |  | 头部那个刚体的名字。⚠️ 嘴虽然有舵机，但 MJCF 里**没有对应关节** —— 它是刚性并进这个 body 的 |
| **`trunk_base`** |  | 躯干刚体。内腔基本被两颗 hip_yaw 舵机占满 |
| **`hip_yaw` / `yaw2roll`** |  | 髋关节的偏航段 / 偏航转横滚的连接件 |
| **`power_support`** |  | 从外面夹住电池的两片结构件（电池是外挂的，有约 40mm 悬在壳外） |
| **`bearing_roll`** |  | ⚠️ 名字里有 bearing 但**不是轴承**，是轴承的压盖，要打印不用买 |
| **`passive_*`** |  | MJCF 里不进动作空间的连杆类别 |
| **`xl330`** |  | 舵机在 MJCF 里的网格名 |
| **Onshape / Part Studio** | Onshape | 上游用的云端 CAD 及其零件建模空间。判断"两个零件是不是同一来源"靠比对 `elementId` |

## 四、机械与结构

| 术语 | 简称 | 一句话 |
|---|---|---|
| **刚体**（rigid body） |  | 仿真中当作不会变形的一整块，Microduck 有 15 个 |
| **关节**（joint） |  | 两个刚体之间允许的相对运动。`hinge joint` = 铰链关节，只能绕一根轴转 |
| **自由度**（DOF, Degree of Freedom） | DOF | 独立可动的方向数。"三自由度的脖子"= 脖子能做三种独立转动 |
| **俯仰 / 横滚 / 偏航**（pitch / roll / yaw） | pitch / roll / yaw | 三个转动方向：点头 / 侧歪 / 左右摇头。舵机命名如 `hip_pitch` 就是这个意思 |
| **运动学树**（kinematic tree） | kinematic tree | 从躯干出发、各关节逐级相连的父子结构。≈ DOM 树，每个节点的位置由祖先累积决定 |
| **减速比**（gear ratio） |  | 电机转多少圈换输出轴转一圈，XL330 是 288.4:1。越大越有劲但越慢 |
| **堵转力矩**（stall torque） |  | 舵机被完全卡住时能输出的最大扭力，单位 N·m。衡量舵机力气的主要指标 |
| **质心**（center of mass） |  | 整机重量的等效集中点。双足机器人能不能站稳基本由它决定 |
| **惯性张量**（inertia tensor） |  | 描述物体绕各轴转动"惯性大小"的 3×3 矩阵，仿真必需的参数 |
| **轴承**（bearing） |  | 让轴能顺滑转动、减少磨损的环形件。这台机器 14 个。⚠️ 极易在 BOM 里漏掉 |
| **舵盘**（servo horn） |  | 装在舵机输出轴上、把转动传给结构件的那个盘或臂 |
| **装配体**（assembly） |  | 多个零件按实际位置组装好的整体模型，与"单件"相对 |
| **爆炸图**（exploded view） |  | 把装配体沿装配方向拉开的示意图，用来看谁装在谁上面。≈ 宜家说明书那种图 |
| **世界变换**（world transform） |  | 把零件从自身坐标系摆到整机坐标系的位移+旋转。应用后导入 CAD 就是装好的样子 |

### 螺丝孔的三种类型

这三个词长得像但完全不同，`fanhao375` 正是靠数这三种孔的直径反推出整机用 M2 螺丝：

| 术语 | 简称 | 一句话 |
|---|---|---|
| **M2 螺丝** |  | 公制螺纹，公称直径 2 mm。M2.5 就是 2.5 mm |
| **过孔**（clearance hole） |  | 让螺杆**穿过去**的孔，比螺杆略大（M2 用 Ø2.2）。⚠️ 与 PCB 的"过孔/via"（层间导通孔）同名不同物，看语境 |
| **沉头孔**（counterbore） |  | 过孔上端扩大的一段，让螺丝头**沉进去**不凸出表面（M2 用 Ø4.4） |
| **攻丝底孔**（tapping hole） |  | 要在里面**切出螺纹**的孔，比螺杆小（M2 用 Ø1.6），螺丝直接拧进塑料 |
| **内六角圆柱头螺丝** | 杯头螺丝 | 头部是圆柱、用内六角扳手拧的螺丝，配沉头孔的标准款 |
| **热熔螺母**（heat-set insert） | 嵌件 / 热熔铜螺母 | 用烙铁压进 3D 打印件的金属螺纹套，比直接拧塑料耐反复拆装得多 |
| **螺纹胶**（threadlocker） | 乐泰 | 涂在螺纹上防震动松脱的胶，俗称乐泰。机器人必备 |
| **包角** |  | 一段圆弧占了多少度。判断某个曲面是不是完整圆孔，就看包角够不够 300° —— 社区靠这个从网格里自动数出所有螺丝孔 |
| **压盖** |  | 压在轴承外圈上、防止它轴向窜动的盖板。⚠️ `bearing_roll` 就是压盖不是轴承 |

## 五、CAD 与 3D 打印

| 术语 | 简称 | 一句话 |
|---|---|---|
| **CAD**（Computer-Aided Design） |  | 画三维零件的软件。本项目定 SolidWorks，理由是与社区可编辑源对齐 |
| **网格**（mesh） |  | 用大量三角面片近似出的曲面表示。渲染和仿真快，但丢失了设计意图 |
| **STL** |  | 最常见的网格文件格式，只有三角面片。**能看能打印，不能改尺寸** |
| **STEP** |  | 保留真实曲面与特征的通用 CAD 交换格式，**可以改**。比 STL 高一个层级 |
| **参数化建模** |  | 模型由"尺寸+约束"生成，改一个数字整体自动更新。≈ 声明式配置 vs 手写产物 |
| **切片**（slicing） |  | 把三维模型切成一层层打印路径的过程，输出打印机能执行的指令。≈ 编译 |
| **3MF** |  | 切片软件（Bambu Studio、PrusaSlicer）用的工程文件，含模型+打印参数 |
| **PLA** |  | 最常用的 3D 打印塑料，便宜好打但不耐热 |
| **URDF** |  | ROS 生态的机器人描述格式，与 MJCF 同类不同派 |
| **DXF** |  | 二维图纸交换格式，本项目用来描述 PCB 板框外形 |
| **填充率**（infill） |  | 打印件内部的填充密度 —— 不是实心。"23% 填充"意味着内部只有 23% 是塑料，其余是空腔 |
| **拓竹 / Bambu Studio** | 拓竹 | 主流 3D 打印机品牌与其切片软件。**MakerWorld** 是它的模型分享平台，支持一键发送到打印机 |
| **PrusaSlicer** | Prusa | 另一款主流切片软件，开源 |
| **onshape-to-robot** | o2r | 把 Onshape 云端 CAD 导出成仿真模型的工具。⚠️ 上游那些 `.part`/`.scad` 就是它的产物，不是谁手工建的模 |

## 六、电子与 PCB

### 板子本身

| 术语 | 简称 | 一句话 |
|---|---|---|
| **打样**（prototyping） |  | 把设计文件发给工厂做出几块实物板。≈ 第一次真上生产环境，错了要重来且要钱 |
| **Gerber** |  | 给 PCB 工厂的标准制造文件，每层铜箔一个文件。≈ 交付给流水线的二进制包 |
| **SMT / 贴片** |  | 把元件贴焊到板面的自动化工艺。"贴片坐标"= 告诉机器每个元件放哪 |
| **位号**（designator） |  | 元件在板上的编号，U 开头是芯片、R 电阻、C 电容、J 接口。≈ 变量名 |
| **DNP**（Do Not Populate） |  | 板上留了位置但**故意不焊**的元件。≈ 声明了但注释掉的配置项 |
| **0603** |  | 贴片元件的封装尺寸代号（0.06×0.03 英寸）。同样阻值不同封装，焊盘不通用 |
| **双层板 / 四层板** |  | 板子里有几层铜。层数越多布线越自由、越贵。HAT 是四层，`imu_to_dxl` 是双层 |
| **整片地**（ground plane） |  | 整层铺满的接地铜，抗干扰用。≈ 全局兜底 |
| **板框**（board outline） |  | 板子的外形轮廓线，决定切割形状与安装孔位置 |
| **立创编号** |  | 立创商城的元件唯一货号。填了它就能一键下单，省掉选型歧义 |
| **嘉立创EDA 专业版** | 立创 / LCEDA | 国产 PCB 设计软件，工程文件后缀 `.eprj2`。本项目 PCB 用它 |
| **KiCad** |  | 开源 PCB 设计软件。官方 HAT 就是 KiCad 工程 |

### 电路概念

| 术语 | 简称 | 一句话 |
|---|---|---|
| **上拉电阻**（pull-up） | 上拉 | 把一根信号线默认拉到高电平的电阻，防止没人驱动时悬空乱跳。≈ 默认值 |
| **悬空**（floating） |  | 一根线没人驱动、电平随机。数字电路里等同于未初始化变量 |
| **去耦电容**（decoupling capacitor） | 去耦 | 紧挨芯片放的小电容，供电瞬间波动时就近补电。≈ 本地缓存扛突发 |
| **串阻**（series resistor） | 串联电阻 | 串在信号线上的小电阻，抑制振铃与过冲 |
| **钳位**（clamping） |  | 把电压强行限制在安全上限内，超过就泄放掉 |
| **TVS** |  | 专门做钳位的二极管，挡瞬间高压尖峰。≈ 限流器 |
| **PPTC / 自恢复保险丝** |  | 过流时自己变高阻断开、冷却后自动恢复的保护件。≈ 熔断器（circuit breaker），真的同名同义 |
| **buck / 降压变换器** |  | 把高电压高效降到低电压的开关电路，如 8.4V → 5V |
| **LDO** |  | 另一种降压方式，简单干净但效率低、发热大 |
| **理想二极管** | ORing | 用芯片模拟出的低损耗单向导通器件，防电流倒灌 |
| **电感**（inductor） |  | buck 电路里储能的线圈，与开关配合完成降压 |
| **MLCC** |  | 最常见的贴片陶瓷电容。⚠️ 有**直流偏压衰减** —— 加上电压后实际容量会大幅缩水，所以选型要留耐压余量 |
| **耐压**（voltage rating） |  | 元件能承受的最高电压，超了会击穿。母线 8.4V 要选 25V 的电容就是这个道理 |
| **热敏电阻**（thermistor） |  | 阻值随温度变化的元件，此处用作过流保护 |
| **晶振**（crystal oscillator） |  | 给芯片提供精准时钟节拍的元件。≈ 系统时钟源 |
| **电源树**（power tree） |  | 电池到各个用电模块的分级供电路径图。≈ 依赖关系图 |
| **配电**（power distribution） | | 把一路电源分给多个部件，顺带降压与加保护。HAT 干的四件事之一 |
| **上电**（power on） | | 给设备通电这个动作本身。「上电前用万用表量正负极」= 通电**之前**先量 |
| **板卡** | | 一块完整的电路板。主控板、扩展板都算，中文口语常说「板子」 |
| **形态**（form factor） | | 板子的外形尺寸 + 接口位置的**事实标准**。「树莓派 Zero 形态」= 65×30mm、40 针排针在固定位置 —— 符合它的配件就能通用。≈ 接口标准，只不过认的是物理尺寸 |
| **RPI** | | Raspberry Pi（树莓派）的常见缩写。⚠️ `RPI Robot HAT` 名字里的 RPI 是历史遗留，Microduck 实际配的是 Radxa |

### 采购与装机实务

淘宝下单和实际接线时会撞上的词，全部来自社区的采购清单与踩坑记录。

| 术语 | 简称 | 一句话 |
|---|---|---|
| **UBEC** |  | 航模圈对降压模块的叫法（Universal Battery Elimination Circuit），把电池电压降到 5V 给主控。⚠️ 买前看**输入下限** —— 很多标 2–6S 的实际 7V 才起步，2S 电池快没电时先掉出稳压 |
| **同步降压 / 非同步** | buck | 同步用 MOSFET 整流，效率高发热小；非同步（如老款 **LM2596**）用二极管，效率低。⚠️ 社区明确建议别买 LM2596 |
| **掉出稳压**（dropout） | dropout | 输入电压低到稳压器维持不住输出，输出跟着往下掉。电池快没电时最容易出现 |
| **AWG** |  | 美制线规，**数字越小线越粗**。18AWG 比 22AWG 粗，能过更大电流 |
| **硅胶线** | 硅胶 | 外皮是硅胶的导线，软且耐温，过关节处比普通 PVC 线耐弯折 |
| **承流线** |  | 走大电流的电源线，与只传信号的线相对。⚠️ 过脖子的承流线才是线束疲劳的真风险，不是那条 MIPI 信号排线 |
| **线束疲劳** | 疲劳断线 | 线材反复弯折导致内部铜丝断裂。关节处必然发生，只能靠留够长度和走线设计缓解。⚠️ 官方没公开任何走线资料 |
| **杜邦线** | 杜邦 | 两端带 2.54mm 插头的跳线，母对母 / 公对母。临时接线万能耗材 |
| **PH2.0 / AMP2.0 端子线** | PH2.0 / AMP2.0 | 两种 2.0mm 间距的接头规格。⚠️ 名字像，物理**不通用** |
| **保险丝 / 快熔** | 快熔 | 过流就烧断的一次性保护件，"快熔"指反应快的类型。与 PPTC（可自恢复）相对 |
| **船型开关 / KCD1** | KCD1 | 按下去会翘起的那种电源开关，KCD1 是最常见的型号系列 |
| **电解电容** | 电解 | 容量大、体积也大的电容，稳住电源母线上的大电流波动。⚠️ 有正负极，装反会爆 |
| **镀锡**（tinning） | tinning | 给裸线头上一层焊锡，防散股、好插好焊 |
| **压线** |  | 用工具把导线压进金属端子。⚠️ 压完先用万用表点一遍，压反了脚序就错了 |
| **台架测试**（bench test） | 台架 | 装进机身之前，先在桌面上把电通起来测一遍。≈ 上生产前先跑一遍集成测试。两个语境：**台架通总线**（零件摊桌上先确认能通信）与**台架实测**（夹具固定单个舵机、加载测力矩转速，用来标定执行器参数——重训策略时需要） |
| **逻辑供电** |  | 给芯片信号部分供的电（3.3V 或 5V），与给电机的功率供电分开。⚠️ 转接板的逻辑供电范围要含 3.3V 才接得上主控 |
| **高耐久 microSD** | High Endurance | 标 High Endurance / 监控专用的卡，比普通卡耐反复写。⚠️ 没有关机检测信号时硬断电容易伤卡 |
| **UAC**（USB Audio Class） |  | USB 音频的标准协议，符合它的声卡在 Linux 下免驱 |

## 七、通信与总线

| 术语 | 简称 | 一句话 |
|---|---|---|
| **半双工**（half-duplex） |  | 同一条线上收发不能同时进行，要切换方向。≈ 对讲机，一次只能一个人说 |
| **单线半双工** |  | Dynamixel 舵机总线的形态：**一根信号线**既发又收，靠方向控制切换 |
| **Dynamixel** | dxl | ⚠️ **同一个词指三样东西**：① 韩国 ROBOTIS 的舵机品牌与产品线（XL330 等）② 通信协议（Protocol 1.0/2.0，字节格式）③ 总线标准（单线半双工 TTL、1Mbps、3 针）。说"换 Dynamixel"通常三层一起换 |
| **STS / SCS** | | 飞特（FeeTech）的舵机系列与对应协议，和 Dynamixel 是同一个位置的东西。SCS 是早期、STS 较新。⚠️ 与 Dynamixel **协议不通用**，接头间距也不同（飞特 2.0mm / Dynamixel 2.5mm）且脚序相反 |
| **总线适配器** | | 把主控的 USB 转成单线半双工总线的**硬件**。Dynamixel 侧是 OpenRB-150 或 U2D2，飞特侧是 URT 系列。⚠️ 换舵机品牌要连它一起换 |
| **协议模块 / 驱动** | | 主控上负责把"转到 30 度"编成字节的那段**软件**。不是硬件。换舵机品牌就换这个类 |
| **UART / TTL 串口** |  | 最基础的两线异步串行通信。`/dev/ttyS2` 就是它在 Linux 下的样子 |
| **串口**（serial port） | | 一次传一个比特的通信口，与「并口」相对。`/dev/ttyS2` 就是 Linux 下的一个串口。≈ 一条双向的字节流管道 |
| **BLE**（Bluetooth Low Energy） | 低功耗蓝牙 | 蓝牙的低功耗分支，适合传少量数据、长期待机。手柄配对与手机 App 走它 |
| **IPC**（Inter-Process Communication） | 进程间通信 | 同一台机器上的进程互相说话。官方用 unix socket 上的 JSON-RPC。≈ 本机内的 RPC，不过网络 |
| **波特率**（baud rate） |  | 串口速率，本项目 1 Mbps。1 个比特只有 1 µs —— 所以方向切换必须硬件做 |
| **DE**（Driver Enable） |  | 半双工总线的方向控制信号，决定此刻是发还是收 |
| **三态缓冲**（tri-state buffer） | tri-state | 能输出高、低、以及"高阻（等于断开）"三种状态的芯片，半双工切方向靠它 |
| **回显**（echo） |  | 发送时自己也收到自己发的字节。本项目固件按发送长度主动丢弃 |
| **I²C** | I2C / IIC | 两线总线（时钟+数据），靠地址区分设备，慢但省线。传感器常用 |
| **SPI** |  | 四线总线，比 I²C 快，一对一为主。IMU 用它 |
| **RS-485** | 485 | 抗干扰的差分串行总线，适合长距离 |
| **从机**（slave / peripheral） |  | 总线上被动应答的设备。`imu_to_dxl` 就是把 IMU 伪装成一个"假舵机"挂在舵机总线上 |
| **寄存器**（register） |  | 设备内部的地址化存储单元，读写它就是在读状态/下命令。≈ 内存映射的 KV store |
| **sync_read** |  | Dynamixel 协议的批量读：一条命令同时问多个设备。≈ 批量查询代替 N 次往返 |
| **Protocol 2.0** | 协议 2.0 | Dynamixel 的通信协议版本，本项目统一用 2.0 |
| **舵机 ID** | ID | 总线上每个舵机的地址。⚠️ 出厂 ID 全相同，必须**一次只接一颗**逐个改，否则分不清谁是谁 |
| **MIPI CSI** |  | 摄像头专用高速接口，那条扁排线 |
| **Stemma / QT** |  | Adafruit 推的免焊 I²C 四线接头规范 |

## 八、传感与控制

| 术语 | 简称 | 一句话 |
|---|---|---|
| **加速度计 / 陀螺仪** | accel / gyro | IMU 的两个组成：前者测直线加速度（含重力），后者测转动角速度 |
| **姿态解算 / 传感器融合** | 融合 / fusion | 把加速度计和陀螺仪的数据融合成"当前朝向"。单独任何一个都不够 |
| **四元数**（quaternion） |  | 用四个数表示三维旋转，不会像欧拉角那样万向锁。姿态的标准表示 |
| **SFLP** |  | LSM6DSV16X 芯片**内置**的融合功能，直接吐四元数 —— 姿态解算不占主控算力 |
| **ToF**（Time of Flight） |  | 发一束光、测往返时间算距离。⚠️ **8×8 区**指一次返回 64 个距离值排成 8×8 的格子（像一张 8×8 像素的深度图），**不是**会旋转扫描的激光雷达 |
| **控制环**（control loop） | control loop | 周期性"读状态 → 算 → 下命令"的循环，本项目 50 Hz（每 20ms 一轮）。≈ 固定频率的事件循环，但**迟到就是故障** |
| **死区开关**（deadman） | | 没人持续下指令就自动归零的机制。手柄断连时机器人不会带着最后一条"全速前进"跑掉 |
| **斜坡**（ramp） | | 让目标值在一段时间内平滑过渡而不是瞬间跳变。上电使能时的 2 秒斜坡就是防止关节猛地弹一下 |
| **低通滤波**（low-pass） | | 滤掉指令里的高频抖动，只让平缓变化通过。头和腿的目标角度都过一遍 |
| **健康门**（health gate） | | 更新后先问"你还正常吗"，不正常就自动回滚。≈ 部署后的健康检查 + 自动回滚 |
| **运动学**（kinematics） |  | 由关节角度算末端位置（正向），或反过来（逆向） |
| **里程计**（odometry） |  | 靠自身传感器推算"我走了多远、朝哪" |
| **标定**（calibration） |  | 测出并补偿每个个体的固有偏差。⚠️ 官方标定流程未公开，是已知缺口 |
| **归零**（homing / zeroing） |  | 装配后把每个舵机的机械零位与软件零位对齐。装错一个关节就全乱 |
| **PWM** |  | 用方波占空比控制平均功率的手段，电机调速的基础 |
| **堵转电流** | 堵转 | 舵机卡死时抽取的电流，XL330 约 1.5A。15 个一起堵转是电源设计的最坏情况 |
| **2S 锂电** | 2S | 两节锂电芯串联，标称 7.4V、满电 8.4V。"S"= series |
| **压降**（voltage drop） |  | 带负载后电压下降的现象。空载 8.4V、带载掉到 6.6V 是正常的 |
| **超压运行** |  | ⚠️ 本项目最反直觉的事实：XL330 额定 3.7–6.0V，官方实际给 6.6–8.2V。好处是力矩更大，代价是发热与寿命 |

## 九、AI、仿真与训练

| 术语 | 简称 | 一句话 |
|---|---|---|
| **强化学习**（RL） | RL | 让智能体在仿真里反复试错、按奖励学会动作，而不是人写规则 |
| **policy（策略）** | 策略 | 训练出来的那个函数：输入当前观测，输出该怎么动。本项目 61 维观测 → 14 维动作 |
| **观测**（observation） |  | 喂给 policy 的状态向量（关节角度、IMU 姿态、速度指令等） |
| **观测维度**（obs_len） | 51 / 61 | 喂给 policy 的数组长度。本项目会遇到两种：**51** = 角速度3 + 重力投影3 + 关节位置14 + 关节速度14 + 上次动作14 + 指令3；**61** = 同样五段，但指令块扩到 13。⚠️ 两者不通用，加载错了直接维度报错 |
| **指令块**（command block） | cmd | 观测里表达"你想让它怎么动"的那一段。旧版 3 个数（前后/左右/转向速度），新版 13 个数（多了身体姿态与头部朝向）。官方 `infer_policy.py` 用 `--new-cmd-obs` 切换 |
| **上次动作**（last action） | | 观测里回灌的上一帧输出。让 policy 知道自己刚做了什么，动作才连贯 |
| **动作空间**（action space） |  | policy 能控制的维度集合。⚠️ 15 个舵机里只有 14 个在动作空间内，第 15 个是嘴 |
| **PPO** |  | 训练 policy 最常用的强化学习算法 |
| **MuJoCo** | mjlab / MJX | 主流机器人物理仿真器。**mjlab / MuJoCo Warp** 是它的 GPU 并行加速版本 |
| **并行环境** | num_envs | 同时跑几千个仿真实例采数据。上游用 4096 个，1–2 小时能训出可用步态 |
| **域随机化**（domain randomization） | DR | 训练时随机扰动质量、摩擦、延迟等参数，逼 policy 学出对误差鲁棒的策略 |
| **sim2real** |  | 仿真里训好的策略搬到实机上。≈ 本地跑通 → 生产环境，中间的差距就是所有麻烦的来源 |
| **backlash（齿隙）** |  | 齿轮换向时的空程间隙，真实舵机有、理想仿真没有。上游专门做了 backlash 变体来补这个差 |
| **BAM** |  | 上游用的执行器模型，让仿真中的舵机行为更接近真实 |
| **步态**（gait） |  | 走路的节奏与姿态模式 |
| **ONNX** |  | 跨框架的模型交换格式。训练用 PyTorch，部署导出成 `.onnx` |
| **推理**（inference） |  | 用训好的模型算一次输出。与"训练"相对 |
| **量化 / INT8** |  | 把模型权重从浮点压成整数，换取更快更省。精度会掉一点 |
| **NPU** |  | 芯片里专门跑神经网络的加速单元。⚠️ Armbian 默认关闭，要刷 overlay |
| **TOPS** |  | 算力单位，每秒万亿次操作。RK3566 的 NPU 约 0.8–1 TOPS |
| **checkpoint** |  | 训练过程中存下的权重快照，可从中断处续训 |

## 十、软件与系统

| 术语 | 简称 | 一句话 |
|---|---|---|
| **SoC**（System on Chip） |  | 把 CPU、GPU、外设集成在一颗芯片上。RK3566 就是 |
| **MCU vs Linux SoC** |  | 单片机跑裸机代码、实时性好但算力弱；SoC 跑 Linux、能干视觉和推流。本项目两者都有：主控是 SoC，`imu_to_dxl` 上是 MCU |
| **设备树**（device tree） | DT / dtb | Linux 描述"这块板上有哪些硬件"的配置文件。≈ 硬件的依赖注入配置 |
| **overlay** |  | 对设备树打的补丁，用来开启默认关闭的外设 |
| **Armbian** |  | 面向 ARM 单板机的 Debian 发行版。**headless** = 不带桌面 |
| **刷写镜像**（flashing） | 刷机 / flash | 把整个系统镜像写进 SD 卡或 eMMC。≈ 部署一个完整的机器镜像而非增量更新 |
| **eMMC / microSD** |  | 板载存储 / 可插拔存储卡。⚠️ 低配 Radxa 无 eMMC，只能从 SD 启动 |
| **daemon** |  | 后台常驻进程。上游把功能拆成 `robotd`、`mediad`、`tofd` 等一组 daemon |
| **JSON-RPC over Unix socket** |  | 上游各进程间的通信方式。App、手柄、脚本调的是同一套接口 |
| **systemd service** | 服务 / unit | Linux 的开机自启与进程守护机制 |
| **WebRTC** |  | 浏览器实时音视频传输协议，用来把摄像头画面推到手机 |
| **GStreamer** |  | 多媒体流水线框架，负责采集、编码、推流 |
| **H.264 硬件编码** |  | 用芯片专用单元压缩视频，省 CPU |
| **OTA** |  | 远程推送固件/软件更新。`updaterd` 负责签名校验与失败回滚 |

## 十一、工程流程

| 术语 | 简称 | 一句话 |
|---|---|---|
| **逆向工程**（reverse engineering） | 逆向 | 从公开产物反推出设计。本项目全部硬件知识都来自这个过程 |
| **设计评审**（design review） | 评审 | 板子打样前请人查错。`fanhao375` 公开原理图求评审就是这个 |
| **勘误**（erratum） |  | 已发布内容的更正。⚠️ 该仓库把"XL330 是 7.4V 舵机"这个错误结论的勘误过程完整留档 —— 这种做法本身值得学 |
| **交叉验证** | 互证 | 两条独立路径得出同一结论才采信。两份独立的 `imu_to_dxl` 重建对上则可信度大增 |
| **代码即规格书** |  | 官方没发规格书，所有硬件参数从源码、设备树、配置文件里反推 —— 这是本项目的方法论 |
